# Qwen AI — AeroSentry 天衡 adapter

The interface ships with a deterministic engine, so `index.html` works on its own.
This folder is how you attach the fine-tuned language model on top of it.

## What the model is

| | |
|---|---|
| Base | `Qwen/Qwen3.5-9B` (Alibaba, released 2026-03-02, dense 9B, 256k context) |
| Method | LoRA SFT — rank 16, alpha 32, target all linear layers |
| Data | 320 domain samples (~377k tokens), all generated by the engine so the model inherits its citation and safety behaviour |
| Task | Turn a verified assessment into natural conversation; answer follow-up questions without inventing numbers |

## Why the weights are not in this repo

The base model is ~19 GB and the merged model is the same size. GitHub rejects files over
100 MB, so the weights are distributed separately:

- Base model: https://modelscope.cn/models/Qwen/Qwen3.5-9B  (or Hugging Face `Qwen/Qwen3.5-9B`)
- Adapter: produced by training, ~34 MB, can be committed once generated

## Attach it to the page

1. Train the adapter (LLaMA-Factory, QLoRA 4-bit, 8 GB VRAM is enough):

   ```bash
   llamafactory-cli train configs/qwen3_5_9b_qlora_8gb.yaml
   llamafactory-cli export configs/merge_lora.yaml
   ```

2. Register it with Ollama using the Modelfile in this folder:

   ```bash
   ollama create aerosentry -f model/Modelfile.aerosentry
   ollama serve
   ```

3. Open `index.html`, click **连接模型** in the top bar, and paste:

   ```
   http://127.0.0.1:11434/v1/chat/completions
   ```

   Model name: `aerosentry`.

The badge in the top bar switches to `aerosentry · 已连接`. If the endpoint is unreachable,
the page falls back to the built-in engine and every conclusion stays identical — the model
changes how it explains, never what is true.
